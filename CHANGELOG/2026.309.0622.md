## Summary

Adds `pod-crabbox-k3s-krun`: the krun-guest k3s lease image for the Crabbox `containerd` provider, one of the `pod-crabbox-<variant>` images tracked by opencharly/opencharly#869 (W5.2). It is the pinned `opencharly/pod-crabbox-k3s` control-plane lease contract plus the `libkrunfw-crabbox` guest kernel at `/krun/vmlinux`, the `/.krun_vm.json` metadata, and the `crabbox.krun.network=passt` label.

- **`charly.yml`** — the image: `base: ghcr.io/opencharly/pod-crabbox-k3s:2026.309.0459` (pinned OCI base), `user: root` with `entrypoint: [/sbin/init]`, and `distro: [cachyos, arch]` + `build: [pac]` declared explicitly because an external OCI base does not inherit the CachyOS chain.
- **`candy/krun-lease/charly.yml`** — the variant layer:
  - a `download:` step fetches the canonical `files/build-kernel.sh` recipe from the pinned `opencharly/layer-krun` tag `v2026.309.0542` into `/tmp/krun/build-kernel.sh` (mode `0755`), and a second `download:` fetches the committed `config-libkrunfw-crabbox.fragment` from the SAME tag;
  - the `krun-guest-kernel` step runs `/tmp/krun/build-kernel.sh` with no environment overrides: the script's defaults are this image's cache, fragment and destination paths. `layer-krun`'s own candy installs and runs the same file (`opencharly/layer-krun#4`), so the recipe exists once (R2);

  - the kernel toolchain (`base-devel`, `git`, `curl`, `tar`, `xz`, `bc`, `perl`, `openssl`, `libelf`, `cpio`, `kmod`, `diffutils`, `rsync`, `python`), kept in the image so the pin can be rebuilt without a new base.
- **Twelve deterministic `check:` steps** — the kernel at the fixed path with mode `0644`, its ELF magic, its size being a real kernel image, both `/.krun_vm.json` keys, and the inherited k3s contract at this boundary (the k3s binary and version, the inner-containerd endpoint, the enabled unit, the systemd init, the lease SSH contract, the uid-1000 `crabbox` user).

### Scope notes

- **Where each requirement comes from.** The row (`/krun/vmlinux`, `/.krun_vm.json`, the label) is `CONTAINERD-IMAGES.md` §2's `pod-crabbox-k3s-krun` entry. The kernel recipe is `opencharly/layer-krun`'s `files/build-kernel.sh`, fetched at the pinned tag; `LIBKRUN.md` §6–§7 give the `.krun_vm.json` keys and the reason the kernel must be custom.
- **The kernel is built, not downloaded as an artifact, because no artifact exists.** No Arch/CachyOS package ships a `libkrunfw-crabbox` vmlinux, and no published image or release asset carries one. The distro's stock libkrunfw kernel is not a substitute: its config disables `CHECKPOINT_RESTORE` and the socket diag options, so in-guest CRIU and the k3s netfilter set fail on it (LIBKRUN.md §7).
- **One recipe, two consumers.** `opencharly/layer-krun#4` exported the recipe as `files/build-kernel.sh`, made the layer's own candy install and run that file, and landed as tag `v2026.309.0542`. This image downloads the same file and runs it. The step sets no environment variables, so there is no second place for the paths to drift.
- **`context: [build]` on the compile step is what keeps the gate clean.** A mutating `run:` step is baked into the plan, and `charly check box` runs verify-only, so an unmarked compile step appears as `SKIP`. The step is a build step, so it is marked `context: [build]`: the build still emits and runs it, and the check plan carries only assertions.
- **`oci_label` lives under the candy's `capability:` block.** It is not an image-node field and not a top-level candy field in this schema; the capability block is the authoring shape, aggregated into the image at resolve time. The generated Containerfile carries `LABEL crabbox.krun.network="passt"` (pasted below).
- **The gate runs under `CHARLY_PLUGIN_ONLY=1`.** The worktree binary already refuses to load the installed package's plugins — that is what its banner says — and `CHARLY_PLUGIN_ONLY=1` removes the condition that emits the banner (`charly/charly/plugin_loader.go:429-444`, an exact `1` match whose early return skips `warnSkippedFHSPlugins`). The resolution path and the validate counts are unchanged; the absence is asserted with `grep -c '^WARNING:'` after each of the four gate commands, all `0`.
- **The kernel build is the long pole.** Locally the full clone-to-vmlinux path took about five and a half minutes on 16 cores; the CI image build passed on this head.
- **Nothing in the image starts a VMM.** The guest boots the inherited k3s control plane; the host's crun/krun runs this image with `krunKernel: image` and `krunNetwork: passt`.
